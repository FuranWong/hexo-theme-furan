# AI 开发规范

本文档定义了 AI Agent 参与本项目开发时必须遵守的行为约束。

---

## 核心原则

1. **低耦合优先**：每次改动只影响一个模块，不产生跨模块副作用
2. **原子化优先**：新增样式优先考虑是否可以拆分为原子，而非写组件专属样式
3. **变量引用**：任何颜色必须引用 CSS 变量，**禁止硬编码 `#xxxxxx`**
4. **Pug 纯净**：模板文件只包含结构，不写内联样式
5. **修改前先读**：编辑任何文件前必须先 `Read` 完整内容，确认上下文

---

## 操作约束

| 规则 | 说明 |
|---|---|
| 禁止随意创建文件 | 新增文件前确认是否可复用现有文件 |
| 禁止删除全局样式后不检查 | 删除 CSS 变量前全局搜索引用 |
| 禁止修改 flavor 令牌文件中的色值 | `tokens/latte.css` 等由 Catppuccin 官方定义，不可自行修改 |
| 新增组件前先讨论 | 避免组件膨胀，确认没有可复用的现有组件 |
| i18n 同步 | 新增文案时必须同步更新所有语言文件 |
| 不得提交未验证的代码 | 修改后检查对应的页面是否正常 |

---

## 标准工作流

```
用户需求
  → 1. 理解需求
  → 2. 搜索代码库，确认影响范围
  → 3. 提出方案，等待用户确认
  → 4. 实施修改（先 Read 再 Edit）
  → 5. 自检清单：
       □ 是否引入硬编码色值？
       □ 是否跨模块耦合？
       □ Pug 中是否有内联样式？
       □ 是否新增了不必要的文件？
  → 6. 通知用户验证
```

---

## 禁止行为

- ❌ 在 Pug 模板中使用 `style=""` 内联样式
- ❌ 在 CSS 中硬编码色值（如 `color: #ff0000`）
- ❌ 在组件 CSS 中直接修改 tokens 变量
- ❌ 跨模块直接引用（如 `header.css` 直接操作 `.sidebar` 的样式）
- ❌ 创建不遵循命名约定的文件
- ❌ 不经确认擅自删除或重构现有代码
- ❌ 引入新的第三方依赖未经讨论

---

## CSS 变量引用速查

所有颜色必须通过以下语义变量引用：

| 语义变量 | 用途 |
|---|---|
| `--accent` | 强调色（链接、按钮高亮等） |
| `--bg-primary` | 主背景色 |
| `--bg-secondary` | 次要背景色 |
| `--bg-card` | 卡片背景色 |
| `--text-primary` | 主文字色 |
| `--text-secondary` | 次要文字色 |
| `--border` | 边框色 |

底层 `--ctp-*` 变量仅在 `tokens/` 文件中定义，其他文件只使用语义变量。

---

## 文件创建检查清单

在新建文件前，依次确认：

1. 是否已有可复用的原子文件？（检查 `atoms/` 目录）
2. 是否已有可复用的组件文件？（检查 `components/` 目录）
3. 是否已有可复用的 Pug partial？（检查 `layout/partial/` 目录）
4. 新文件的命名是否符合现有约定？
5. 新文件是否真正承担不可复用的独立职责？

全部通过后才可创建新文件。
